### 2.2 领域 Agent（核心亮点，务必写足）

| 成果 | 位置 | 作用 |
|---|---|---|
| 推理引擎 | `app/agent/engine.py` | 规则约束 + 打分排序，生成候选搭配并给出理由点 |
| 知识库检索 | `app/agent/kb.py` | 领域知识切片索引与检索，作为 LLM 参考资料（RAG） |
| LLM 调用层 | `app/agent/llm.py` | 智谱 GLM-4-Flash；`ask()` 普通生成、`ask_stream()` SSE 流式；含超时降级 |
| 衣物画像 | `app/agent/garment_profile.py` | 单品属性归一与画像构建 |

**架构要点（写概要设计时直接引用）**：分层为「前端 → 接口层 → Agent 引擎 → 规则库/知识库 → 数据层」。Agent **不是纯 LLM**，而是「规则引擎负责可行性与打分（可解释、可复现）+ LLM 负责自然语言解释与追问」，LLM 不可用时降级为模板回复。这是本项目与普通 ChatGPT 套壳的关键区别，也是评分点。

## 六、交接方式（建议 3 步）

1. **30 分钟走查会**：开发端讲「分层架构 → Agent 如何决策 → 一次对话的数据流（前端→接口→引擎→规则库→DB→LLM→SSE 回推）」，撰写端当场提问并确认术语。
2. **素材包冻结**：约定 D0 晚 22:00 冻结，之后技术内容变更走 issue，避免 PDF 与代码不一致。
3. **双人互审**：撰写端出稿后，开发端只核对三件事——图与代码是否一致、接口/字段名是否准确、缩写是否都有定义。
