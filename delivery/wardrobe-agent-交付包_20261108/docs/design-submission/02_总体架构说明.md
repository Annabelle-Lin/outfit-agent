# 总体架构说明

## 一、设计目标与约束

本系统是一套对话式穿搭推理智能体，目标是盘活用户已有的衣物：用户把自己的衣物录入电子衣橱后，系统结合实时天气、穿着场合、体型特征与个人偏好，通过自然语言对话给出可解释的搭配方案，并支持多轮调整、反馈学习与购前评估。项目在课程实践的真实约束下推进，需要同时满足三类要求。其一是可解释与可复现，每一次推荐结论都必须能追溯到具体规则与知识来源，而不是由大模型自由生成；其二是零成本与可降级，全部技术选型基于免费组件，外部服务缺失时系统仍能运行；其三是轻量易演示，单体后端加单页前端即可在一台普通电脑上完整启动，不依赖复杂的分布式环境。

## 二、分层架构

系统整体采用分层架构，自上而下分为五层，各层职责单一、依赖方向只向下依赖，不允许下层反向依赖上层。

第一层是表示层，即 `frontend/index.html` 单页应用。它负责登录注册、引导建档、今日穿搭、电子衣橱、对话、购前评估、历史记录与个人资料八个视图的渲染与交互，通过 `fetch` 调用后端接口，不包含业务判定逻辑。

第二层是接口层，由 FastAPI 的七个路由模块构成，对应用户、衣物、天气、对话、反馈、购前评估、上传七类接口。该层负责接收请求、调用鉴权中间件、借助 Pydantic 完成入参校验、组织业务调用并返回统一响应结构。

第三层是 Agent 推理层，是系统的核心，包含推荐引擎、知识库检索、大模型调用与单品画像四个部件。推荐引擎负责组合枚举、硬过滤、打分排序与理由生成，已实现；知识库检索负责领域文档的切片索引与召回，已实现；单品画像负责属性归一与推断，已实现；大模型调用层在目标架构中负责自然语言组织，当前大模型尚未接入、该部件未启用，自然语言输出暂由本地模板与检索结果承接，完整多轮对话机制也待进一步确认，当前以静态原型演示对话界面。

第四层是规则与知识层，包含 `rules/` 目录下四份 JSON 规则库与 `data/s3_kb/` 目录下的领域知识库。规则以配置文件形式存在，与引擎代码解耦，修改规则不需要改动程序；知识库文档逐条标注来源，是推理与问答的事实依据。

第五层是数据层，由 SQLAlchemy 与 SQLite 组成，负责七张数据表的持久化、会话管理与轻量迁移，同时以静态目录方式提供上传图片访问。

## 三、技术选型及理由

后端语言选择 Python 3.10 以上版本，原因在于团队对其熟悉，且 FastAPI、SQLAlchemy 以及大模型、检索相关生态都以 Python 为主，能够用较少的集成成本覆盖 Web 服务、ORM、检索与 AI 调用全部需求。Web 框架选择 FastAPI，它原生支持异步、依赖注入与自动生成的交互式接口文档，配合 Uvicorn 即可运行，开发联调效率高。

持久化方面选择 SQLAlchemy 2.x 加 SQLite 的组合。SQLite 是文件型数据库，无需安装独立服务，一个库文件即可支撑演示，符合轻量约束；SQLAlchemy 以 ORM 方式屏蔽 SQL 方言差异，模型类即数据字典，且保留了未来切换到其他数据库的能力，只需修改 `DATABASE_URL` 配置。

Agent 部分采用“规则引擎为主、大模型为辅”的混合路线而非纯大模型方案。规则引擎负责可行性判定与打分，结果确定、可复现、可追溯，这部分已落地；大模型在目标方案中仅承担自然语言解释与知识问答生成，当前大模型接入尚未实现，系统默认以本地模板与检索结果承接，因此在完全离线时仍能完成推荐主流程。这一设计使项目不依赖大模型即可运行，是本项目区别于简单套壳聊天应用的关键，大模型接入与多轮对话机制列入后续计划。

知识检索选择 jieba 分词加 rank-bm25 的 BM25 方案，并以同义词扩展和 RRF 融合做混合检索。BM25 不依赖外部服务、在小规模专业知识库上效果稳定且可解释；同义词扩展解决“大衣”与“外套”等字面不重合导致的漏召回问题。天气数据选择 Open-Meteo，它零密钥、非商用免费、提供地理编码与实时天气接口，配合本地坐标表与三十分钟缓存即可满足需求。

前端不引入重型框架，采用单文件 HTML 加原生 JavaScript 实现，配合 CSS 变量统一莫兰迪配色。这样前后端可以由 FastAPI 静态挂载一体化启动，也便于把页面结构直接作为原型工具重绘的底稿。

## 四、部署与运行形态

系统采用单体部署形态。后端通过 `uvicorn app.main:app --port 8300` 启动，应用在生命周期事件中依次完成规则库加载、数据库建表与知识库索引构建；前端与上传目录由 FastAPI 以静态文件方式挂载，因此一个进程同时提供页面、接口与图片访问。数据库文件默认放在用户主目录下的 `.wardrobe` 文件夹，避免项目目录无写权限；全部外部密钥通过 `.env` 注入，不写死在代码中。

## 五、架构层面的关键机制

其一，统一响应与鉴权。所有接口返回 `{code, msg, data}` 结构，鉴权中间件在路由之前统一校验 Bearer 令牌并拦截越权访问，白名单之外的业务接口一律受保护。其二，兜底机制贯穿全系统，天气与视觉识别两类外部能力均有明确的本地路径；大模型当前未接入，模板与检索结果是现阶段默认输出而非临时降级，所有路径都在返回字段中如实标注数据来源，不把估算值伪装成实时结果。其三，规则与代码解耦，规则库和知识库均为可独立替换的文件，每条规则带 `source` 字段、每条知识带来源标注，支撑答辩时的溯源展示。
