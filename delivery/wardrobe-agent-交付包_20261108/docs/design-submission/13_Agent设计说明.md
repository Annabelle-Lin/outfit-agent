# 领域 Agent 设计说明

## 零、实现状态说明

本章描述领域 Agent 的目标架构与完整推理方案，各部分当前实现状态先行区分。基于规则引擎的推荐内核已经落地，包括组合枚举、硬过滤、打分排序、差异化取前三与理由生成，以及单品画像、本地 BM25 知识检索能力，这部分不依赖大模型，可独立运行。尚未实现的部分有两处：其一是大模型接入，智谱 GLM-4-Flash 的实际调用与密钥配置当前未接入，涉及自然语言生成的环节暂以本地模板与检索结果兜底；其二是完整对话机制，多轮意图识别、会话状态流转与澄清交互的具体机制仍待进一步确认，当前以静态原型演示对话界面形态。下文凡涉及大模型与多轮对话的内容，均按目标设计方案描述，列入后续开发计划。

## 一、Agent 的定位

本系统的领域 Agent 是一个对话式穿搭推理智能体，定位为“可解释的穿搭顾问”而非通用聊天窗口。它要解决的核心问题是：在用户已有的衣物集合内，结合实时天气、穿着场合、体型特征和个人偏好，推理出合法且优质的搭配方案，并在多轮对话中理解用户的调整意图、持续学习偏好、回答穿搭知识问题以及辅助购前决策。

Agent 与普通大模型聊天应用的根本区别在于决策架构。它不是把请求直接交给大模型生成答案，而是采用“规则引擎负责可行性与打分、大模型负责自然语言表达”的混合架构。规则引擎的结论确定、可复现、可逐条追溯到规则编号与知识来源；大模型只在规则给出的事实框架内组织语言，不参与可行性判定。当大模型不可用时，系统降级为模板回复，推荐主流程不受影响。

## 二、内部结构

Agent 由四个部件协同构成。推荐引擎 `engine.py` 是决策中枢，包含规则仓库与推荐流程，规则仓库在启动时一次性加载四份 JSON 规则文件并在进程内复用，该部件已实现。知识库检索 `kb.py` 负责把领域文档切片、建索引并按查询召回参考片段，本地 BM25 检索能力已实现。大模型调用层 `llm.py` 在设计上封装智谱 GLM-4-Flash 的问答、流式输出与推荐文案生成，当前大模型尚未接入，该部件处于已封装、未启用状态，实际输出走本地模板。单品画像 `garment_profile.py` 负责品类归一、暖度与季节推断、重复度计算，解决录入数据不完整导致规则失效的问题，该部件已实现。

## 三、任务处理主流程

目标方案中，用户提出请求后，对话路由在后端统一做意图识别，把原文分流为推荐、知识问答、单品改良、反事实对比、约束更新等动作，再进入相应处理链路；其中意图识别与多轮路由属于待确认的对话机制。推荐主链路本身已实现，按以下顺序执行。

第一步是组合枚举，引擎把衣橱单品按品类分组，枚举“上装＋下装＋鞋”和“连衣裙＋鞋”两类基础组合，并可选叠加外套与配饰，同时为每个组合生成基于单品标识的指纹。第二步是硬过滤，依次执行温度、场合、色彩、完整性、用户约束等规则，淘汰不合法组合。第三步是排除已展示方案，避免重复推荐。第四步是打分，以六十分为基础，按临时偏好、长期偏好、色彩协调、版型比例、暖度契合、面料季节、体型适配等规则加权，得到零到一百的分数。第五步是按分数降序并做差异化处理，取前三套且要求彼此至少替换一件核心单品。第六步是生成可解释理由并持久化方案快照。自然语言回复环节在目标方案中由大模型结合本轮需求组织，当前大模型未接入，统一使用本地模板文案。

## 四、领域知识与规则依据

Agent 依赖的领域知识沉淀在 `data/s3_kb/` 的七份知识库文档中，覆盖服装色彩构成、造型与版型体型适配、材料与面料特性、场景着装礼仪、胶囊衣橱管理、推理规则与偏好学习机制、真题与案例六个领域，共八十二条知识点、四十三份来源，每条知识都标注出处。规则层取用 `06_推理规则与偏好学习机制说明` 中的硬性规则，话术层引用各文档中的可解释模板，枚举值取自标签枚举文件。规则库 JSON 中的每条规则都带 `source` 字段，标明其来自服装材料学、色彩构成理论、着装礼仪规范等，答辩时可直接溯源。

## 五、工具调用与系统集成

Agent 在后端进程内以函数方式调用工具，不依赖外部 Function Calling 协议。其可调用的工具包括：天气工具，经 Open-Meteo 获取实时温度与降雨概率；规则引擎，执行硬过滤与打分；知识检索工具，执行 BM25 混合召回；大模型工具，生成问答与文案；以及业务数据读写，经 ORM 访问用户、衣物、会话、反馈、评估、方案各表。

Agent 与系统的关系是深度内嵌而非独立外挂。它通过 ORM 直接读取用户衣橱与画像数据，推荐结果写回方案表，会话上下文写回会话表，反馈结果驱动偏好重算，购前评估复用同一套规则。一次完整请求的数据流为“前端→接口层→Agent 引擎→规则库/知识库→数据层→大模型→流式或同步返回前端”，各环节共享同一后端进程与数据库。

## 六、知识问答与 RAG 流程

目标方案中，当意图被识别为知识问答时，Agent 走检索增强生成链路。知识库在启动时扫描全部 Markdown 文档，按二级、三级标题切片，超长表格做专用切分，使用 jieba 分词并构建 BM25 索引，这部分已实现。查询时同时构建原词通道与同义词扩展通道，各自打分后用 RRF 倒数排名融合，召回前五片段，检索环节已可用。大模型生成环节当前未接入，因此系统直接把检索到的原文片段整理展示并标注来源；待大模型接入后，再改为把片段连同对话上下文交给模型、由模型依据资料作答。

## 七、降级与可靠性设计

Agent 对外部依赖设计了兜底，当前实际生效的是天气与图片两条路径。大模型当前未接入，问答以原文摘录呈现、推荐以模板文案回复，这是现阶段的默认形态而非临时降级，待模型接入后才启用生成式回答。天气接口失败时返回模拟数据并标注来源，城市无法识别时明确提示而不伪造温度；天气完全未知时不执行任何天气相关过滤与打分，避免用假设温度误导推荐。图片识别在无视觉模型时使用本地主色与文件名启发式，并标注原因。所有路径都在返回字段中如实标注数据来源，不把估算值伪装成确认结果。

## 八、偏好学习与多轮交互

多轮交互属于待确认的对话机制，当前以静态原型演示其界面与目标交互。目标方案中，用户可通过“不要黑色”等自然语言设置排除色、替换品类、临时偏好等约束，后端解析后更新会话状态，该机制随对话方案一并确认后落地。偏好学习本身不依赖大模型，已实现的部分是：用户对方案的反馈以喜欢、一般、不喜欢三档记录，系统按全部反馈重算五个维度的长期偏好，保证幂等；每条反馈记录其偏好增量，支持逐条撤销并精确回退。目标方案还规划了会话推荐额度，先校验后扣减、额度用尽时提示，将与对话机制同步实现。
