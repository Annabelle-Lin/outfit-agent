# 功能模块清单

> 本清单按后端模块与 Agent 部件逐项说明职责、输入、输出与依赖，模块划分与 `app/` 目录、`frontend/index.html` 视图一一对应。
>
> 实现状态口径：用户、衣物、天气、反馈、购前评估、上传及 Agent 的规则引擎、知识库检索、单品画像为已实现；对话模块的完整多轮机制待进一步确认，大模型（GLM-4-Flash）接入未实现，当前以静态原型演示对话界面，相关自然语言输出走本地模板与检索结果。

## 一、用户模块

用户模块对应 `app/api/user.py`，前端对应登录注册视图与个人资料视图，承担账号与个人画像管理。其职责包括账号注册、登录、账号可用性检查、资料查询与更新、体型数据维护、长期偏好查询与重置、用户数据清空。输入为注册登录凭证、资料与体型字段；输出为登录令牌、用户信息与统计数据。该模块依赖安全模块完成密码摘要与令牌签发，依赖 ORM 操作用户表，并在登录时统计衣物、反馈、评估、会话数量。需要说明的是，系统只有普通注册用户一种角色，不存在管理员角色，权限边界是“用户只能访问本人数据”。

## 二、衣物模块

衣物模块对应 `app/api/clothing.py`，前端对应电子衣橱视图与新增衣物弹窗，承担电子衣橱的全部管理职能。其职责包括衣物的新增、列表查询、单件详情、修改、删除、整柜清空，以及标签枚举获取、Excel 批量导入与导入模板下载。输入为衣物属性、品类筛选参数或 Excel 文件；输出为衣物数据、分页列表、枚举字典或模板文件。该模块依赖规则库中的标签枚举做校验，依赖 ORM 操作衣物表，借助 openpyxl 处理 Excel，并通过安全模块校验单品归属。

## 三、天气模块

天气模块对应 `app/api/weather.py`，承担实时天气获取。其职责是按城市名返回温度、降雨描述与降雨概率。输入为城市名，缺省为福州；输出为天气信息与来源标识。该模块内置二十个常用城市坐标表，未知城市调用 Open-Meteo 地理编码接口，天气数据来自 Open-Meteo 预报接口，进程内缓存三十分钟，外部失败时降级返回模拟数据或城市无法识别提示，不编造温度。

## 四、对话 Agent 模块（核心，机制待确认）

对话模块对应 `app/api/chat.py`，前端对应对话视图，规划为系统的核心模块。其目标职责包括创建会话、发送消息、会话列表与详情、结束会话，以及流式问答，并在后端统一完成意图识别，把请求分流为推荐、知识问答、单品改良、反事实对比、约束更新、接受与拒绝等动作，同时维护会话额度。当前完整多轮对话机制仍待进一步确认，大模型接入尚未实现，对话界面以静态原型演示；模块内已可复用的是规则引擎推荐内核与本地知识检索。输入为用户原文与动作参数；目标输出为搭配方案、回答文本、约束确认或额度提示。该模块规划依赖推荐引擎、知识库、大模型层、天气模块与全部业务表，是各部件的编排中枢。

## 五、反馈模块

反馈模块对应 `app/api/feedback.py`，承担偏好学习。其职责包括提交反馈、查询反馈历史、查看反馈对偏好的影响、撤销单条反馈。输入为喜欢、一般、不喜欢的评级及标签评论；输出为反馈记录与重算后的偏好。该模块不做增量累加，而是按用户全部反馈重新计算五个维度的偏好，保证幂等；撤销采用墓碑标记，记录保留但不再参与重算，从而精确回退分数。

## 六、购前评估模块

购前评估模块对应 `app/api/purchase.py`，前端对应购前评估视图，承担新品购买决策支持。其职责是对拟购单品评估其与现有衣橱的可搭配套数、重复度、自身合理性并给出购买建议，同时提供评估历史与删除。输入为拟购单品属性及可选的季节、气温、城市；输出为评估结论、搭配示例与建议等级。该模块复用推荐引擎同一套枚举与硬过滤规则，借助单品画像模块推断暖度与季节，按 Jaccard 相似度计算重复度，气温来源按“用户传入、实时天气、季节默认值”的优先级解析并如实标注。

## 七、图片上传模块

上传模块对应 `app/api/upload.py`，承担图片存储与属性识别。其职责包括上传图片返回可访问地址，以及上传后识别衣物属性供表单预填。输入为图片文件；输出为图片地址、识别属性、识别来源与缺失字段。该模块限制八兆大小与八种格式，识别分三段进行：有视觉模型时调用模型，无模型时用图片主色与文件名启发式，都失败时返回缺失字段清单，每段都显式标注来源，不夸大识别能力。

## 八、Agent 内部部件

除路由模块外，Agent 推理层包含四个内部部件。推荐引擎位于 `app/agent/engine.py`，负责规则库加载、组合枚举、硬过滤、打分、差异化取前三与理由生成，输出最终搭配，已实现。知识库检索位于 `app/agent/kb.py`，负责扫描 Markdown 文档、按标题切片、构建 BM25 索引并以同义词扩展加 RRF 融合完成召回，检索能力已实现。大模型调用位于 `app/agent/llm.py`，设计上封装智谱 GLM-4-Flash 的普通问答、流式输出与推荐文案生成，当前模型未接入、部件未启用，实际输出由本地模板承接。单品画像位于 `app/agent/garment_profile.py`，负责品类与季节归一、子品类推断、暖度推断及 Jaccard 重复度计算，已实现。

## 九、模块依赖关系汇总

| 模块 | 主要依赖 | 被谁依赖 |
|---|---|---|
| 用户模块 | 安全模块、用户表 | 前端个人资料视图 |
| 衣物模块 | 规则库、衣物表、openpyxl、安全模块 | 对话模块、前端衣橱视图 |
| 天气模块 | Open-Meteo、httpx | 对话模块、购前评估模块 |
| 对话模块（机制待确认） | 推荐引擎、知识库、天气、业务表；大模型未接入 | 前端对话视图（原型演示） |
| 反馈模块 | 反馈表、用户表、工具函数 | 前端反馈入口 |
| 购前评估模块 | 推荐引擎、单品画像、衣物表、天气 | 前端评估视图 |
| 上传模块 | 文件系统、PIL（可选）；视觉模型未接入 | 衣物与评估表单 |
| 推荐引擎 | 规则库、单品画像 | 对话、购前评估模块 |
| 知识库 | jieba、rank-bm25、Markdown 文档 | 对话模块 |
| 大模型层（未启用） | 智谱接口、httpx（规划） | 规划供对话、上传模块使用 |
